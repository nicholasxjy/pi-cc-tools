已在当前仓库完成性能优化，并补充了可重复基准和回归测试。主要收益来自减少重复布局、限制差异计算和清理后台资源。

## 实测性能

基线为提交 `4c32f8f`，与优化版本使用同一份基准脚本。每个版本运行三个独立 Node 进程，下表取各场景平均耗时的中位数。

| 场景 | 优化前 | 优化后 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 200 个运行中工具，重复绘制 | 0.388 ms | 0.002 ms | 99.4% |
| 20,000 行日志，追加一行 | 0.769 ms | 0.383 ms | 50.2% |
| 20,000 行结果，首次预览 | 230.300 ms | 13.00 ms | 94.4% |
| 20,000 行结果，失效后重绘 | 216.916 ms | 0.317 ms | 99.9% |
| 5,000 个不同单词的单行替换 | 2947.751 ms | 4.77 ms | 99.8% |
| 1,500 行内容全部替换 | 221.126 ms | 6.59 ms | 97.0% |

环境为 macOS arm64、Node v26.13.0、终端宽度 100 列。组件测试使用 Pi Coding Agent 0.79.10 和 Pi TUI 0.79.1。

这些数字衡量组件处理和布局耗时，包含场景内必要的更新工作。它们不能换算成整个程序的帧率、CPU 或内存下降比例。

原始三轮数据、CPU 时间和对比结果保存在 `docs/performance-results.json`。

## 资源占用的变化

| 资源 | 验证结果 | 实际作用 |
| --- | --- | --- |
| 大结果的布局缓存 | 20,000 行降至 5 行 | 减少隐藏行的带样式文本和补齐空格缓存 |
| 流式日志的旧内容扫描 | 追加两行时，全缓冲区逐行扫描次数从 20,002 降至 0 | 复用旧行统计，只重新处理末行和新增部分 |
| 运行中分组的状态读取 | 100 个工具重绘 20 次，从 10,000 次降至 0 | 内容、时间和动画不变时直接复用布局 |
| 终端焦点监听器 | 模块重新求值 6 次后，仅增加 1 个监听器 | 后续重载替换旧监听器 |
| 本地标签退出监听器 | 模块重新求值 6 次后，数量不增长 | 避免重复保存与退出清理 |
| 标签订阅 | 同一行重绘 100 次仍只有 1 个回调 | 标签到达时减少重复失效与重绘 |
| 标签助手积压 | 1,000 个请求最多保留 20 个未完成请求 | 限制助手停滞时的内存和待处理工作 |
| JSON、RPC 显示定时器 | 创建次数为 0 | 后台调用保留统计，省去终端动画 |
| 旧 UI 的全局引用 | 删除无用写入，并在重载时清理旧引用 | 释放无用途保留的 UI 对象图 |

布局缓存的行数是实测对象数量。完整输出仍保存在结果中；本次没有给出整个进程的 RSS 降幅。

## 具体改动

| 位置 | 改动 | 解决的问题 |
| --- | --- | --- |
| `extensions/index.ts` 的 `ToolGroupComponent` | 将内容变化、动画阶段和显示时间纳入缓存条件 | 运行中分组反复遍历全部工具 |
| `ToolText` 和 `CodemodePreview` | 只保留可见行布局，复用未变化的结果组件 | 大输出反复换行、补齐和分配数组 |
| `branchIndent` | 普通缩进省去无用的主题颜色解析 | 首次预览对每个隐藏行重复查色 |
| `collectLiveToolLines` | 增量统计追加内容，并处理未完成末行 | 日志越长，每次更新越慢 |
| `wordDiffAnalysis` 和 `parseDiff` | 为词级和行级比较设置工作预算 | 大范围替换阻塞交互线程 |
| `renderSplit` | 只为预览范围分配成对的行对象 | 折叠状态仍为整份差异创建布局对象 |
| 编辑预览和执行 | 以内容缓存解析结果，复用已定位的差异 | 缩放、展开及执行阶段重复解析 |
| `extensions/bash-file-edit.ts` | 使用 Set 按原顺序去重路径 | 大量文件路径造成二次方查找 |
| `extensions/bash-intent.ts` | 限制积压、复用订阅、清理重载状态 | 标签助手停滞和重复订阅增加资源占用 |
| `extensions/terminal-theme.ts` | 注册新监听器前移除旧监听器 | 重载次数越多，输入处理越重 |
| `extensions/spinner.ts` | 按显示模式调度动画，释放旧 UI 引用 | 无界面模式仍持续运行显示任务 |

本次没有新增依赖，也没有新增用户配置项。

## 计算边界与取舍

词级比较的字符串总长度上限为 8,192，编辑距离上限为 128。超过预算时保留整行增删着色。

行级比较的编辑距离上限为 256。超过预算时，保留公共首尾和中间替换文本，并显示简化提示。此时的增删统计对应简化差异，不保证最小差异。

标签助手达到 20 个未完成请求时，后续命令仍正常执行，界面继续显示原命令，省去该次标签生成。

首次预览仍需读取和统计完整输入。大量宽字符、极长单行和真实终端吞吐仍会影响首帧耗时。

本次没有测量长时间运行的真实终端 RSS、耗电或 Apple 本地模型吞吐。原始输出和会话数据的内存仍由 Pi 管理。

## 复测与启用

在仓库根目录运行：

```bash
npm test
npm run typecheck
node --experimental-strip-types scripts/benchmark-performance.mts
```

确认 Pi 加载的是这份本地扩展后，重启 Pi 使改动生效。重启也会清理旧版本已经累积的监听器。

后续可用相同会话和终端尺寸，对比输入响应、日志滚动和系统资源监视器中的进程占用。
